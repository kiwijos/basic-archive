# The demo is seeded through the public API, keyed by where each record came from

`make demo` brings an empty cluster to a working demo: deploy, wait for readiness, load the data, check it. The loader (`seed/`, run as `python -m archive_seed seed|check`) is a client of catalog-api like any other: it calls the staff API over HTTP with a staff token, so it needs no database access, no new endpoint that skips the rules, and it exercises the code a person would. Rejected: SQL or a database dump, which would bypass the outbox events that feed OCR and search and teach nothing about the API; a Kubernetes Job inside the cluster, which would need the seed data in an image and a build for every change to it.

**Idempotency comes from source keys, not from matching names.** `subject` and `document` already had `source_system` and `source_id` columns with unique indexes (migration 0001). Ticket #11 exposes them: both are given or neither, and `GET /ships|/organisations|/documents?source_system=&source_id=` finds a record by its key (a system's records may be listed, but never everything: `source_system` is required). The loader looks a record up by key before making it, adds only what is missing (names, relations, pages, links), and treats a 409 on create as another run having got there first. A seed that is killed at any request and run again ends with exactly what one clean run makes; the tests kill it before and after each of several changes to check. The key is immutable, shared by Ships and Organisations, and stays reserved after a soft delete, so seeding after someone deleted a seeded ship stops with an error that says so instead of making a twin. This also gives later imports a place to say where a record came from.

**Verification states are made the way a person would make them.** The loader waits until every page has been read by the real worker, measures the machine reading against the text the scan was made from, and only then adds a human transcription to the pages that are meant to be verified (a person's text on a page the worker has not reached would make the archive refuse the machine reading, and there would be nothing to measure). Some Documents stay machine-only and one is verified on its first page only. Accuracy is the machine reading's, whether or not a person has corrected the page since, and a rerun measures the same thing.

**Real drawings, synthetic documents.** The fleet and its 13 Documents are invented, in Swedish, with no persons (ADR 0002), so nothing needs a licence; they are rendered with deliberate damage so the OCR figures are not all 100 %. Large drawings to zoom into come from four public-domain Chapman plates on Wikimedia Commons, fetched at seed time by exact address and checked against a recorded SHA-256, kept in a local cache and not committed (about 30 MB of images). Offline, they are skipped out loud and `make demo` still passes; a file that does not match its checksum stops the seed. A drawing has no running text, so the OCR reads noise from it and a person's note stands in, and plates are left out of the accuracy figures. Sources and rights are in `seed/SOURCES.md`.

**`make demo` ends with the demo check, not the smoke test.** The check only reads: every seeded record can be opened from the public search index, an old name finds its ship, a seeded scan and a plate are served as tiles, and the accuracy is measured. The smoke test creates about 25 throwaway Documents that cannot be deleted (there is no delete for Documents), which a demo must not contain, so it stays a separate command (`make smoke`). `make reset` deletes the namespace after the name is typed, so the next `make demo` starts from nothing.
